# Готовность Next.js MVP

Проверено 4 октября 2026 года. Источник истины — текущие файлы проекта. Это локально проверенный MVP; публикация обновлённого production и подключение облачных сервисов ещё не выполнены.

Текущая структура главной: Hero с trust signals → видео (при наличии) → форматы → о ведущей → принципы работы → реальные фотографии (при наличии) → процесс → услуги/расчёт и доступ к календарю → отзывы (при наличии) → FAQ → финальный CTA → footer. Дата, услуги и контакты объединены в одно окно бронирования.

## Проверки

- Production build Next.js проходит; страницы `/`, `/admin`, `/privacy`, `/robots.txt`, `/sitemap.xml`, API и uploads включены в сборку.
- 40 unit/integration-тестов проходят на Node.js 24.21.0: backend, адаптер Next Request/Response, CMS, конкурентные правки, изображения, VK mock, cloud-preflight и прежний SEO-генератор.
- `test`, `test:experience`, `test:loading`, `test:mvp-browser` проходят: расчёт/заявка/админка, календарь, галерея, публикация материалов, восстановление связи, no-JS, задержка загрузки, повтор после тайм-аута, reduced motion.
- Chromium: ширины 320–1920 px без горизонтального переполнения; проверки axe WCAG A/AA без нарушений в проверенных состояниях; без console/runtime/hydration errors.
- Визуально просмотрены desktop/mobile Hero: `artifacts/mvp-hero-1440.png`, `artifacts/mvp-hero-390.png`.
- Автотесты используют отдельные каталоги. Реальная `.data` не заменялась тестовыми отзывами, фото или заявками.
- SQL обновлён, но не выполнен в настоящем Supabase: настройки доступа отсутствуют. Это ограничение проверки, а не подтверждённая работа облачной записи.

## Что требуется для публичного запуска

1. **C1/C2 — инфраструктура.** Создать Supabase, применить актуальный server/schema.sql, настроить серверные переменные Vercel, пройти read-only preflight и тест записи в отдельной базе. Сейчас check:cloud сообщает об отсутствии SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY. Production без облака намеренно возвращает 503 для приёма заявок.
2. **ВК.** Получить токен сообщества и точный peer_id разрешённого диалога, включить уведомления и проверить реальную доставку. Токены в репозиторий не добавлять. Интеграция не имеет фоновой очереди, доступен ручной повтор.
3. **B2/B3/I4/T4 — материалы владельца.** Опубликовать реальные фотографии разных форматов, ролик и отзывы с разрешением авторов. Технические места и редактор готовы, контент нельзя достоверно сгенерировать вместо реальных кейсов.
4. **B4/B5 — условия.** Подтвердить минимальную длительность, состав техники, выезд, предоплату, перенос и отмену. Сайт не обещает отсутствующие условия. Для подтверждённых условий есть редактор закрытых черновиков и публикация в FAQ. Изменяемые описания услуг доступны в админке.
5. **P4 — измерения.** Включить выбранные продукты аналитики Vercel и build-time флаги, затем измерять реальные мобильные LCP/CLS/INP и конверсию. Локальные тесты не заменяют полевые данные.
6. **M2 — браузеры.** Выполнить проверку на настоящем iPhone/Safari. Chromium с мобильным viewport не является тестом iOS.

## Следующий этап после первых реальных материалов

- S2: отдельные содержательные страницы свадеб/корпоративов/юбилеев с реальными кейсами, видео и условиями. Не создавать пустые SEO-дубли текущих вкладок.
- F1: постепенно переносить оставшиеся DOM-контроллеры админки на React hooks/components, сохраняя действующие API-контракты и тесты. Текущая миграция не выдаётся за полную перепись всей интерактивности на React.
- P2/P3: дальнейшее разделение CSS и загрузки галереи — после замеров с настоящими материалами, без увеличения сложности ради формального уменьшения количества файлов.
- N1: более глубокие эффекты, A/B-тесты и расширенные dashboards после данных о конверсии. 3D и тяжёлые декоративные зависимости не возвращались.
## Этап: React-редактор материалов

Редактор видео и отзывов перенесён из DOM-контроллера в React-компоненты и отдельный hook. Существующий API, CSRF и управление сессией сохранены. Добавлены предпросмотр публикации, счётчик опубликованных/черновых отзывов, видимый лимит 12 отзывов, отмена правок и копирование текста при конфликте. Незавершённые запросы не восстанавливают данные после выхода; после истечения сессии черновик остаётся в памяти вкладки до повторного входа. В localStorage/sessionStorage тексты не записываются. Палитра не менялась, новых зависимостей нет.

Регрессионная проверка `npm run test:content-editor` включена в CI. Проверены публикация, XSS-safe предпросмотр, две вкладки, отказ от обновления, лимит, clipboard fallback, повторный вход, запоздавший ответ после logout, ширины 320/390/1440 и axe. Облачные ограничения из списка выше остаются в силе.

## Этап: React-вкладки форматов

Выбор свадьбы/корпоратива/юбилея/выпускного перенесён в `components/site/FormatTabs.jsx`. Содержимое карточек остаётся серверным, без JavaScript доступны все четыре ссылки. Удалён запуск прежнего DOM-контроллера (сохранён в `legacy/formats.js`); переключение выполняется React state, мягкая анимация — CSS с отключением при reduced motion. Связь с калькулятором сохраняет выбранные услуги, количество часов и сумму. Проверки клавиатуры, no-JS и сохранения расчёта добавлены в существующие browser suites. Цветовая система не менялась.
## Этап: единый путь от услуг к заявке

Главные CTA открывают календарь первым шагом с сохранением уже выбранных параметров. Если дата неизвестна, доступен явный переход «Дату выберем позже». Календарь переводит к услугам, затем к контактам; пустой расчёт явно обозначает первую бесплатную консультацию. Контактный шаг показывает повод, дату, услуги, количество и предварительную сумму из того же расчёта, который отправляется на сервер. Возврат к редактированию сохраняет контактный черновик в памяти страницы; при обновлении каталога после конфликта обновляется и видимый итог заявки.

Сохранены проверки даты, серверный пересчёт, версии каталога и ключ повторной отправки. Палитра и API-контракты не менялись. Проверки охватывают основной и финальный CTA, сохранение услуг/часов/встреч, передачу параметров, возврат к редактированию, бесплатную консультацию, повтор после тайм-аута, доступность и ширины 320/390/1440 px. В локальном preview проверен календарь из подбора услуг; настоящие заявки при этой проверке не отправлялись.

## Этап: измерение шагов бронирования

События conversion теперь отражают фактическое открытие окна (booking_open), календаря (calendar_open), услуг (services_view), контактов после проверки даты (request_open) и успешное сохранение (lead_saved). Клик, который не прошёл проверку, не считается открытой заявкой. Передаются только фиксированные названия действий; внешнего коллектора пока нет. Возврат к редактированию расчёта остаётся на услугах и сохраняет черновик контактов.

## Этап: React-галерея и просмотр по запросу (F1, P2/P3)

Сетка и просмотр перенесены в `GalleryClient`, `GalleryTile` и `GalleryLightbox`. Серверный `Gallery` сохраняет заголовок секции. `public/gallery.js` стал небольшим адаптером общего каталога; прежний контроллер сохранён в `legacy/gallery.js`. Дополнительного запроса каталога нет. Код просмотра выделен в отдельный chunk и по сетевой проверке не загружается до клика по фото. Добавлены загрузка, отмена ожидающего открытия и сообщение с повторной попыткой при ошибке загрузки модуля.

Сохранены порядок/обложка/черновики из админки, lazy-изображения с размерами, обработка битых фото, Escape/стрелки/свайпы, возврат фокуса, reduced motion и существующая палитра/композиция. Пустая галерея скрыта. Реальный каталог не наполнялся тестовыми материалами. Новый `test:gallery` включён в CI: проверяет общий запрос, отложенный chunk, отмену без позднего открытия, безопасные подписи/URL, одну/пустую галерею, 320/390/1440 px и axe. Существующие site/experience suites и проверка локального Turbopack также проходят. Снижение полевых LCP/INP не заявляется; реальные материалы и замеры по-прежнему нужны.

## Этап: React-подбор услуг и единый состав сметы (F1)

Карточки услуг, категории и счётчики основной страницы и окна бронирования перенесены в `ServicePicker` / `ServiceOption`. Оба интерфейса используют один выбор и существующие ограничения `booking-rules`; расчёт и API-контракт сохранены. Некорректное количество не меняет сумму, после выхода из поля возвращается последнее корректное значение. Списки позиций на странице и в контактном шаге используют один компонент `QuoteLines`, включая тарифы «от», часы, встречи и удаление позиции. DOM-контроллер больше не создаёт карточки и строки сметы вручную. На этом этапе форма и календарь ещё использовали DOM-контроллер; текущий статус описан ниже.

Проверены на Node.js 24: site и loading suites (сохранение выбора, границы количества, удаление услуг и консультаций, конфликт тарифов, отправка, offline/retry, доступность). Сборка и check проходят. Локальный Turbopack: 320/390/1440 px, палитра, дата → услуги → контакты, изменение расчёта с сохранением черновика; без runtime/hydration ошибок. Preview восстановлен на 127.0.0.1:4173; рабочие заявки при визуальной проверке не отправлялись.


## Этап: единое React-бронирование (3 октября 2026)

Календарь, переходы, контакты и отправка перенесены в React. `BookingProvider` хранит общий выбор для окна и блока стоимости, `Calendar` проверяет доступность с отменой устаревших ответов, `RequestForm` обрабатывает валидацию, ошибки и подтверждение. Дата → услуги → контакты находятся в одном native dialog. Сохраняются черновик контактов при переходах, состав расчёта и возможность уточнить дату позже. Персональные данные не сохраняются в sessionStorage. Старые три обработчика вынесены в legacy и исключены из public/PageScripts.

Палитра сохранена. В окне компактные категории и строки услуг, заметный итог, раскрываемая детализация на контактном шаге, закреплённые заголовок/шаги и единая прокрутка на телефоне. Анимации отключаются при reduced motion. Исправлены контраст номеров шагов, выбранная дата при наведении и очистка даты без сброса просматриваемого месяца.

Проверки: production build и check; site, experience, loading, booking suites на Node.js 24; также mvp-browser и gallery. Проверены изменение цены через настоящую тестовую админку, сохранение заявки в изолированном хранилище, повтор после тайм-аута с тем же requestId, новый requestId при редактировании состава после ошибки, отмена запоздавшей проверки при закрытии окна, отсутствие старых обработчиков, axe и ширины 320–1920 px. Мобильная клавиатура моделировалась уменьшенным viewport Chromium; отдельного прогона на физическом iPhone/Android не было. Локальные рабочие заявки не создавались и .data не изменялась.

Скриншоты: artifacts/booking-react-calendar-390.png, artifacts/booking-react-services-390.png, artifacts/booking-react-services-1440.png, artifacts/booking-react-contact-390.png. test:booking добавлен в CI. Это завершает миграцию публичного бронирования, но не означает подключения облачного production: Supabase, ВК, реальные материалы, условия и публикация остаются внешними пунктами готовности.


## Этап: контроль готовности к публикации (4 октября 2026)

В админке появился сворачиваемый React-блок «Подготовка к запуску»: постоянное хранение, доступ к управлению, согласованность HTTPS-адресов и состояние настройки ВК. Это проверка конфигурации, без обещания запущенного production. Облачное подключение проверяется отдельной кнопкой только после задания серверных переменных. Общий модуль server/cloud-check.mjs используется и в CLI, и в защищённом API. Пять независимых GET-запросов запускаются параллельно; каждый ограничен 15 секундами. Данные клиентов, ключи и тела ошибок не возвращаются в браузер.

Новые API /api/admin/launch-status и /api/admin/cloud-check требуют действующей сессии. Диагностика не инициализирует SQL-схему, не изменяет локальное/облачное хранилище и не отправляет ВК. Неверный метод отклоняется до обращения к хранилищу. При выходе результаты очищаются; поздний ответ не восстанавливает их в следующей сессии. Обновление настроек не сбрасывает черновики услуг.

Проверки: production build, check, deployment/cloud-check/mvp unit-интеграционные suites; deployment-browser, content-editor и booking browser suites. Новые тесты включены в CI. Chromium: 320/390/1440 px, axe, XSS-safe вывод статусов, сохранение черновика, отключение кнопки без настроенного облака и поздний ответ после logout. Реального Supabase и ВК по-прежнему нет; check:cloud сообщает об отсутствии SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY. Скриншоты настоящих локальных настроек: artifacts/launch-settings-1440.png и artifacts/launch-settings-390.png; остальные launch-status скриншоты используют тестовые ответы.

## Завершение технической подготовки

Добавлены редактор подтверждённых условий с закрытыми черновиками, серверной валидацией и публикацией в FAQ; обратная совместимость старых CMS-запросов сохраняет условия. Цена и материалы имеют независимые версии. Видео и отзывы перенесены на общий React-каталог, старый site-content.js убран из публичной загрузки.

Аналитика подключается штатными скриптами Vercel по отдельным build-time переключателям. По умолчанию ничего не отправляется. События ограничены фиксированными названиями, URL очищаются, admin и Do Not Track исключаются. Реального коллектора и полевых данных пока нет; проверка выполнена с mock-скриптами.

Бронирование проверено в Chromium и WebKit с мобильными настройками: все шаги, отмена запоздавшей проверки, повтор после ошибки, редактирование услуг, приватность черновика, 320/390/1440 px и axe. Визуальная проверка WebKit выявила светлую нативную поверхность select; добавлены appearance:none и dark color-scheme с прежними цветовыми переменными.
