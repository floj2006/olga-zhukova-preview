# Заявки, каталог и админ-панель

Целевая версия сервера — Node.js 24, без дополнительных runtime-зависимостей. Публичный сайт получает каталог через `/api/catalog`; итоговая сумма и заявка всегда проверяются сервером. Пароль и ключ Supabase не попадают в `dist/` или JavaScript браузера.

## Локальный запуск

1. Выполните `node scripts/setup-admin.mjs` из корня проекта.
2. Откройте **локальный** файл `artifacts/admin-access.txt`: в нём адрес панели и сгенерированный пароль. Скрипт не выводит пароль в терминал и не перезаписывает существующие настройки.
3. Запустите или перезапустите `npm run dev`.
4. Откройте `http://127.0.0.1:4173/admin/`.

Настройки находятся в `.env.local`, данные — в `.data/state.json`, фотографии — в `.data/uploads/`. Все эти файлы должны оставаться вне Git и вне публичной папки. Один локальный процесс обслуживает запросы последовательно при записи и заменяет JSON атомарно. Резервная копия `.data/` сохраняет каталог, календарь, заявки и изображения; не запускайте несколько локальных серверов с одной папкой данных одновременно. Старые локальные данные автоматически получают пустой календарь; каталог и заявки сохраняются.

Можно задать собственный пароль через переменную окружения `ADMIN_SETUP_PASSWORD` перед запуском скрипта. Длина — 12–256 символов. Пароль хранится на сервере как `scrypt$<32 hex salt>$<128 hex hash>`: N=32768, r=8, p=1, 64 байта результата. `ADMIN_SESSION_SECRET` — случайная строка не короче 32 символов. Для смены доступа создайте новый хеш и секрет в отдельной временной папке тем же скриптом, перенесите их в `.env.local` и перезапустите сервер. Смена хеша или секрета аннулирует все прежние сессии.

## Vercel и постоянное хранилище

Локальные файлы не используются как база в serverless. При `VERCEL` или `NODE_ENV=production` API **возвращает 503**, пока постоянное хранилище и доступ администратора не настроены. Статический сайт может открываться, но успешная отправка заявки не имитируется.

1. Создайте проект Supabase и выполните [server/schema.sql](../server/schema.sql) в SQL Editor. Он создаёт таблицы, транзакционные функции и публичный бакет `olga-gallery`. Таблицы закрыты RLS; права на них и функции есть только у серверной роли. Публично доступны сами фотографии, а не заявки и не запись в галерею.
2. В переменных окружения Vercel задайте `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_PASSWORD_HASH`, `ADMIN_SESSION_SECRET` и `APP_ORIGIN=https://ваш-домен`. Хеш и секрет можно взять из локально сгенерированного `.env.local`; для боевого сайта лучше использовать отдельный пароль. Ключ берите из настроек Supabase; он остаётся только на сервере. `SUPABASE_GALLERY_BUCKET` по умолчанию равен `olga-gallery`.
3. Разверните проект. Обработчик [обработчик Next](../app/api/%5B...path%5D/route.js) использует [server/index.mjs](../server/index.mjs). При первом обращении начальный каталог из [catalog-default.json](../server/catalog-default.json) вставляется только если каталога ещё нет. Изменённые администратором цены не сбрасываются при новом деплое.
4. Войдите в `/admin/`, измените тестовую цену, отправьте тестовую заявку, проверьте её в панели и загрузите изображение. Перезапуск или новый деплой не должны удалять данные.

При обновлении уже работающего Supabase повторно выполните `server/schema.sql`: он добавит `olga_availability` и функции календаря/порядка галереи без сброса существующих данных. Пока схема не обновлена, недоступный календарь возвращает ошибку, а не список якобы свободных дат.

`APP_ORIGIN` должен совпадать с адресом, по которому открыта панель: запросы с другого origin отклоняются. Для preview используйте соответствующий адрес и отдельные переменные окружения/хранилище. В текущей рабочей папке наличие кода адаптера не означает, что облачная база уже создана: её нужно подключить своими реквизитами.

Адаптер использует [Postgres-функции Supabase](https://supabase.com/docs/guides/database/functions) для атомарных операций и [Supabase Storage](https://supabase.com/docs/guides/storage/uploads/standard-uploads) для фото. REST-запросы выполняет стандартный `fetch` Node.js. Сервисный ключ не требует установки SDK.

## Контракт API

- `GET /api/catalog` — `{version, services, gallery, firstMeetingFree:true}`. Публично возвращаются только активные услуги.
- `POST /api/quote` — `{items:[{id,quantity}],extraMeetings}` → `{lines,total,from,version}`. Тарифы приходят из серверного каталога; присланная браузером цена игнорируется.
- `POST /api/leads` — те же параметры плюс `name`, `phone`, необязательные `eventType`, `eventDate`, `comment`, `catalogVersion`, обязательные `consent:true`, `requestId` (UUID), пустое поле `website`. Возвращает `{id,ok:true,quote}` только после сохранения. Повтор с тем же requestId и данными возвращает сохранённую заявку; изменение данных с тем же ID даёт 409. Если `catalogVersion` устарела, ответ 409 с `code:"catalog_changed"`, актуальными `quote` и `catalog` требует подтверждения новой суммы.
- `POST /api/admin/login` — `{password}` → `{authenticated:true,csrfToken}` + cookie. `GET /api/admin/session` возвращает состояние входа и CSRF-токен, 401 до входа. `POST /api/admin/logout` удаляет cookie.
- `GET /api/admin/catalog` возвращает также неактивные услуги. `PUT /api/admin/catalog` принимает `{version,services}` и возвращает обновлённый каталог. Изменение устаревшей версии даёт 409.
- `GET /api/admin/leads?offset=0&limit=50` — `{leads,offset,limit,hasMore}`. Максимум 100 заявок на страницу. `PATCH /api/admin/leads/:id` принимает `{status,note}`; статусы `new`, `contacted`, `booked`, `closed`.
- `GET /api/availability?month=YYYY-MM` — `{month,busyDates:["YYYY-MM-DD"]}`. Только занятые даты выбранного месяца: заметки, ID и контакты не публикуются. Ошибка хранилища возвращает 503 без `busyDates`; клиент не должен считать месяц свободным при ошибке.
- `GET /api/admin/availability` — `{version,dates:[{id,date,status:"busy",note,createdAt,updatedAt}]}`. `PATCH /api/admin/availability` принимает `{version,changes:[{date,busy,note?}]}` и возвращает обновлённый календарь. Одним запросом можно изменить 1–366 уникальных календарных дат. `busy:false` удаляет занятость и заметку, `busy:true` с отсутствующей `note` сохраняет прежнюю заметку. Максимум 2000 символов заметки. Версия календаря независима от цен; устаревшая версия возвращает 409 с `code:"availability_changed"`, без частичной записи. После конфликта нужно загрузить календарь и предложить проверить изменения.
- `POST /api/admin/gallery` принимает `{dataUrl,alt,caption?,featured?,width?,height?}` и возвращает `{photo}`. JPEG/PNG/WebP до 3 МиБ с проверкой сигнатуры, максимум 200 фотографий. `featured` — boolean (по умолчанию false); `width`/`height` передаются парой, целые 1–16384. Имена файлов генерируются сервером. `PATCH /api/admin/gallery/:id` частично меняет `{alt?,caption?,featured?}`, `DELETE` убирает фото.
- `PUT /api/admin/gallery/order` принимает `{ids:[...все текущие ID в новом порядке]}` и возвращает `{gallery}`. Изменение сохраняется атомарно; повторяющиеся ID дают 400, неполный или устаревший набор — 409 с `code:"gallery_changed"`. Публичный `/api/catalog` отдаёт фотографии в сохранённом порядке, с `featured` и размерами, без внутренних имён файлов.

Дополнительные встречи указываются только через `extraMeetings` (0–20); первая консультация бесплатна. Идентификатор `consultation` нельзя повторно передавать в `items`. Часы — целое число 1–24, комплекты — 1–10. Дублирующиеся идентификаторы и недоступные услуги отклоняются. Снимок выбранных услуг, тарифов и суммы сохраняется вместе с заявкой и не меняется при последующем редактировании каталога.

Все изменяющие запросы используют JSON. Административные изменения дополнительно требуют `x-csrf-token`. Cookie: HttpOnly, SameSite=Strict, срок 8 часов, Secure на HTTPS/production. Проверяется Origin. Вход ограничен 8 попытками за 15 минут с одного IP, заявки — 12 запросами за час; IP хранится только в виде HMAC-ключа лимита. В production лимиты разделяются между serverless-инстансами через PostgreSQL.

## Проверка

### Календарь и расширенная галерея

После обновления выполните `server/schema.sql` в уже настроенном Supabase: он добавляет таблицу `olga_availability` и функции для календаря и порядка галереи. Существующие каталог, заявки и фотографии сохраняются. Локальное хранилище получает поле `availability` автоматически и атомарно, без сброса данных.

- `GET /api/availability?month=YYYY-MM` возвращает `{month,busyDates:["YYYY-MM-DD"]}`. В ответе нет идентификаторов записей, заметок или контактных данных. Ошибка хранилища возвращает ошибку, а не пустой список свободных дат.
- `GET /api/admin/availability` возвращает `{version,dates:[{id,date,status:"busy",note,createdAt,updatedAt}]}`.
- `PATCH /api/admin/availability` принимает `{version,changes:[{date,busy,note?}]}` — от 1 до 366 уникальных корректных дат за запрос. Изменения сохраняются атомарно; устаревшая версия даёт `409 availability_changed`. `busy:false` снимает отметку и удаляет связанную заметку. Версия календаря не меняет версию тарифов. Авторизация, CSRF и Origin проверяются как у остальных административных изменений.
- `POST /api/admin/gallery` дополнительно принимает `featured:boolean` и пару `width,height`. Браузер принимает исходные JPEG/PNG/WebP до 20 МБ, уменьшает длинную сторону до 2048 px и отправляет изображение не более 3 МиБ. Сервер продолжает проверять размер и сигнатуру.
- `PATCH /api/admin/gallery/:id` позволяет независимо менять `alt`, `caption` и `featured`.
- `PUT /api/admin/gallery/order` принимает `{ids:[все текущие ID в нужном порядке]}` и возвращает `{gallery:[...]}`. Неполный или устаревший набор отклоняется; порядок сохраняется на сервере. В публичный каталог включаются только поля, нужные для показа фото, без внутренних имён файлов.

Календарь показывает предварительную доступность. Заявки не создают автоматических броней и не изменяют занятость. Обе стороны подтверждают событие при личном общении; занятые даты отмечаются в панели.

`node --test tests/backend.test.mjs` проверяет расчёты и валидацию, запись после перезапуска, повторную отправку, изменение цен, авторизацию/CSRF/origin, порядок и избранные фото, календарь и приватность заметок, атомарные конфликты, миграцию старых данных, лимиты входа и отказ production без настроек. Интеграция с настоящим Supabase требует заданных реквизитов и отдельной проверки после настройки облака.


## Первичная настройка доступа

Можно сначала скопировать .env.example в .env.local: setup:admin заполняет пустые поля доступа без дублирования ключей. Уже настроенные или частично заполненные реквизиты не перезаписываются.

Для другого локального порта до первого setup задайте ADMIN_SETUP_ORIGIN, например http://127.0.0.1:4174. APP_ORIGIN должен совпадать с адресом открываемой админки; иначе изменение данных будет отклонено. Пароль появляется только в локальном artifacts/admin-access.txt и не выводится в терминал.

Код и схема базы отправляются в Git; .env.local, .data и private access file исключены. Git push не создаёт Supabase и не переносит в него локальные заявки.
### Формат хеша в Next.js

В файлах .env Next.js раскрывает переменные с символом $. Поэтому setup:admin записывает разделители хеша как \$; при загрузке Next получает исходный scrypt-хеш. Повторная настройка исправляет только экранирование ранее созданного хеша, сохраняя пароль и ключ сессии.

В панели переменных Vercel задавайте сам хеш с обычными $, без обратных слешей: там значение уже является переменной окружения и не читается из .env-файла. Не публикуйте ни один вариант хеша.
