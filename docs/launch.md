# Публичный запуск

Техническая часть проверяется локально. Успешная сборка и пакет не означают подключение production. Секреты и реальные заявки не включаются в пакет публикации.

1. В проекте Supabase владельца применить server/schema.sql. Затем выполнить read-only server/verify-schema.sql: все 15 строк должны быть true. Проверка ограничена настройками RLS, доступом к таблицам/функциям и стандартным бакетом. Она ещё не выполнена в реальном облаке.
2. Задать на Vercel серверные переменные из .env.example: облачное хранение, хеш пароля, ключ сессии, точный HTTPS APP_ORIGIN и такой же SITE_URL. Для preview использовать отдельную базу. Ключ Supabase никогда не получает браузер.
3. В отдельной тестовой базе пройти сценарии заявки, повторной отправки, изменения цен, занятости даты, конфликта CMS и загрузки/скрытия фото. npm run check:cloud и проверка в админке делают только чтения.
4. ВК: настроить токен сообщества и VK_PEER_ID разрешённого диалога по vk-notifications.md. Включать VK_NOTIFICATIONS_ENABLED после проверки. Заявки сохраняются до уведомления, сбой доставки виден в админке; повтор доступен вручную.
5. Через админку опубликовать реальные фото, ссылку на видео и отзывы с разрешением авторов. Подтверждённые условия заполнить в «Материалы». Тестовые примеры из автотестов не переносятся в рабочую базу.
6. При необходимости включить Web Analytics / Speed Insights в Vercel и build-time флаги. События конверсии включаются отдельно и требуют поддерживаемого тарифа. Проверить живые события и полевые LCP/CLS/INP после публикации; локальный прогон их не заменяет.
7. Опубликовать preview для проверки. Для production привязать домен к проекту владельца, пересобрать с правильным SITE_URL, проверить HTTPS, canonical/robots, телефон и полный путь заявки. Production без облака отклоняет приём заявок; это намеренное ограничение.
8. Проверить сайт на физическом iPhone/Safari и Android, включая календарь и клавиатуру. Автотест WebKit проверяет движок, а не устройство.

Для публикации можно использовать подготовленный artifacts/release-*/site/ как корень проекта Next. Архив не содержит секретов, локального хранилища или старого dist. Локальные данные автоматически в облако не переносятся.

На 4 октября 2026 доступы Supabase, ВК и Vercel отсутствуют. Сетевые запросы к Vercel из текущего окружения завершались тайм-аутом. Новая публичная ссылка пока не получена. Достоверность внешних сервисов проверяется после появления доступа.

Отправка подготовленного preview-архива в codex-deploy-skills.vercel.sh/api/deploy отклонена автоматической проверкой разрешений: требуется явное согласие владельца на передачу исходников этому внешнему сервису. Запрос отправлен; без ответа загрузка не выполняется.
