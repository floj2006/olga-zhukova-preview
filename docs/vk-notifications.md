# Уведомления ВК

Интеграция опциональная. Основной источник заявок — админка; отключение или сбой ВК не отменяет сохранение заявки.

## Настройки

В серверное окружение добавьте:

```dotenv
VK_NOTIFICATIONS_ENABLED=true
VK_COMMUNITY_TOKEN=SECRET_COMMUNITY_TOKEN
VK_PEER_ID=RECIPIENT_PEER_ID
```

Нужны токен сообщества с доступом к сообщениям и точный `peer_id` диалога, в котором сообщество имеет право отправлять сообщения. Не используйте личный токен и не размещайте секреты в `public/`, Git или чате. `APP_ORIGIN` должен указывать на сайт с админкой; для production требуется HTTPS.

До настройки держите `VK_NOTIFICATIONS_ENABLED=false`. Само заполнение получателя не предоставляет сообществу доступ к диалогу — это настраивается на стороне ВК. Токен и получатель в текущем проекте не настроены, реальные сообщения в ходе разработки не отправлялись.

## Поведение

После сохранения заявки сервер вызывает официальный `messages.send` (API 5.199) с тайм-аутом 4 секунды. Уведомление содержит дату, если она задана, и ссылку `/admin`; контакты и комментарий остаются в админке. `random_id` стабилен для заявки и используется для дедупликации повторов.

Статус `sent` или `failed` записывается рядом с заявкой. При `failed` в карточке есть «Повторить уведомление ВК»; API требует вход и CSRF-токен, ограничивает частоту повторов. Автоматической очереди повторной доставки нет. Если сервер завершится сразу после сохранения заявки, уведомление может остаться неотправленным; сама заявка будет в админке.

Перед включением на production проверьте доставку в отдельном тестовом диалоге с разрешением владельца. Unit/integration-тесты используют mock-ответы и не подтверждают доступ реального сообщества.
